# ساخت نسخهٔ نصبی دفتر نسیه از گیت‌هاب

این پروژه شامل نسخهٔ وب و پروژهٔ اندروید است. نسخهٔ ۲۲ روی این کامپیوتر با SDK اندروید ساخته و Android lint و آزمون‌های بومی صف بکاپ بررسی شده‌اند؛ GitHub Actions هم همین بررسی‌ها را انجام می‌دهد. آزمون‌های منطق حسابداری و مقصدهای بکاپ از داده و شبکهٔ شبیه‌سازی‌شده استفاده می‌کنند؛ ورود واقعی به درایو، تحویل واقعی تلگرام و دقت صدای صاحب گوشی باید روی گوشی تأیید شوند.

## ۱. آپلود

ZIP آماده را استخراج کن و **محتویات آن** را به ریشهٔ مخزن قبلی ببر: index.html و پوشه‌های css، js، android، scripts، tests و **.github** باید کنار هم باشند. خود ZIP یا یک پوشهٔ اضافه دور پروژه را آپلود نکن. پوشهٔ .github ممکن است در انتخاب فایل پنهان باشد؛ حتماً وجود `.github/workflows/android-apk.yml` را در گیت‌هاب بررسی کن. اگر فایل در آپلود انتخاب نشد، Add file → Create new file را بزن، این مسیر را دقیق وارد کن و محتوای فایل محلی را کپی کن. فایل‌های قدیمیِ build workflow مربوط به پروژهٔ دیگری را همراه این پروژه اجرا نکن.

آپلود با Add file → Upload files → Commit changes انجام می‌شود. برای اجرای دستی، این فایل‌ها باید در شاخهٔ پیش‌فرض مخزن باشند. این مسیر با GitHub Pages جداست؛ Pages برای APK لازم نیست.

## ۲. ساخت آزمایشی

Actions → Build Android APK → Run workflow → build_type: **test** → Run workflow.
پس از سبز شدن اجرا، همان اجرا را باز کن؛ پایین صفحه در Artifacts، **nasie-test-apk** را دانلود کن. ZIP خروجی را باز کن و فایل app-debug.apk داخل آن را نصب کن. در صورت نیاز اجازهٔ نصب از مرورگر/مدیر فایل را در اندروید بده.

این نسخه فقط برای آزمایش با حساب نمونه است. شناسهٔ آن `ir.nasie.offline.test` است؛ امضای debug سرور ثابت تضمین‌شده نیست. برای نگهداری حساب واقعی و به‌روزرسانی‌های بعدی، نسخهٔ release را بساز. test و release دو برنامهٔ جدا هستند و اطلاعات خودکار بین آن‌ها منتقل نمی‌شود. اگر نصب debug جدید خطای امضا داد، ابتدا بکاپ بگیر؛ برای حذف نسخهٔ دارای حساب عجله نکن.

## ۳. ساخت نسخهٔ اصلی با امضای ثابت

اگر کلید امضای همین برنامه را از قبل داری، آن را نگه دار. این پروژه شناسهٔ `ir.nasie.offline` دارد؛ تا شناسه و کلید نسخهٔ قبلی مشخص نباشد، نمی‌توان آن را به‌روزرسانی مستقیم APK قدیمی دانست.

اگر کلید نداری، روی کامپیوتر Java JDK 17 نصب کن، PowerShell جدید را در پوشهٔ پروژه باز کن و اجرا کن:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\create-signing-key.ps1
```

این دستور فقط کلید می‌سازد؛ Android Studio لازم ندارد. کلید و چهار فایل TXT در پوشهٔ `Nasie-signing-private` داخل پوشهٔ کاربری ساخته می‌شوند؛ خارج از پروژه. از این پوشه یک نسخهٔ خصوصی و امن نگه دار. این فایل‌ها را به بخش Code مخزن، پیام یا Issue نفرست. برای آپدیت‌های بعدی کلید جدید نساز.

در مخزن: Settings → Secrets and variables → Actions → New repository secret. چهار secret زیر را با **محتوای** فایل TXT هم‌نام بساز:

- ANDROID_KEYSTORE_BASE64
- ANDROID_STORE_PASSWORD
- ANDROID_KEY_ALIAS
- ANDROID_KEY_PASSWORD

حالا Actions → Build Android APK → Run workflow → build_type: **release**.
خروجی **nasie-release-apk** شامل app-release.apk امضاشده است. شمارهٔ نسخه با هر اجرای همین workflow افزایش می‌یابد. برای نسخه‌های بعدی از همین مخزن، همین workflow، همین شناسه و همین کلید استفاده کن؛ جابه‌جایی مخزن/بازنشانی شمارنده ممکن است به تنظیم versionCode نیاز داشته باشد.

## ۴. انتقال حساب‌ها و بررسی گوشی

قبل از انتقال، در برنامهٔ قبلی خروجی JSON بگیر و وجود فایل را بررسی کن. نسخهٔ اصلی APK را نصب کن، بکاپ را از تنظیمات وارد کن و تعداد مشتری‌ها، تراکنش‌ها و چند مانده‌حساب را با نسخهٔ قبلی مقایسه کن. نسخهٔ قبلی را تا پایان بررسی حفظ کن. اطلاعات مرورگر یا APK دیگری خودکار به این برنامه منتقل نمی‌شود.

ابتدا با حساب نمونه این موارد را روی گوشی بررسی کن:

- در حالت پرواز برنامه را باز کن، مشتری و تراکنش بساز، برنامه را کامل ببند و دوباره باز کن؛ مانده باید حفظ شود.
- خروجی JSON بگیر، محل ذخیره را انتخاب کن و پیام «فایل بکاپ ذخیره شد» را ببین. لغو پنجره نباید پیام موفقیت بدهد. سپس فایل را در برنامه وارد کن و مانده را بررسی کن.
- میکروفون را امتحان کن؛ متن و برداشت‌های دیگر باید قبل از ثبت قابل بازبینی باشند. هیچ صدا یا متن موقتی خودکار تراکنش ثبت نمی‌کند.
- با همان کلید یک release جدید بساز و روی قبلی نصب کن؛ حساب نمونه باید باقی بماند.

## آفلاین و نگهداری اطلاعات

تمام HTML، جاوااسکریپت، فونت‌ها و کتابخانهٔ اکسل داخل APK قرار می‌گیرند. حساب‌ها در حافظهٔ خصوصی اندروید ذخیره می‌شوند؛ ثبت فقط بعد از نتیجهٔ موفق نوشتن حافظه معتبر است. نسخهٔ قبلی حساب، بکاپ پیش از بازیابی و سه بکاپ روزانهٔ محلی حفظ می‌شوند. نسخهٔ نصبی به Web Locks مرورگر وابسته نیست؛ Activity از نوع singleTask است. بکاپ خودکار سیستم‌عامل خاموش است؛ بکاپ بیرون از برنامه همچنان ضروری است. حذف برنامه یا Clear storage اطلاعات داخل آن را پاک می‌کند.

در نسخهٔ ۲۲، گفتار فارسی به‌طور پیش‌فرض با مدل Vosk همراه APK و بدون اینترنت انجام می‌شود. بار اول مدل در حافظهٔ خصوصی آماده می‌شود؛ برای بارهای بعد در حافظهٔ برنامه گرم می‌ماند. برای آزمون، «ویرایش» تنظیمات → «بررسی آمادگی مدل فارسی» را بزن و بعد در حالت پرواز صحبت کن. دقت صوتی به صدا، لهجه و محیط وابسته است؛ متن، مشتری و مبلغ پیش از ثبت قابل اصلاح و تأیید هستند. اگر خواستی سرویس قبلی را استفاده کنی، روش گفتار را «آنلاین» انتخاب کن. حالت آفلاین وب‌مرورگر تضمین نمی‌شود؛ مدل داخل APK است. مدل رسمی fa-0.42 حدود ۵۳ مگابایت و APK کامل به‌همراه کتابخانه‌های بومی حدود ۱۰۰ مگابایت است. منبع و مجوز مدل در پوشهٔ licenses هستند.

## تنظیمات ذخیره‌شده

در حالت عادی هیچ ورودی تنظیمات یا کلیدی در صفحه باز نیست. «ویرایش» اطلاعات را باز می‌کند و «پایان ویرایش» دوباره می‌بندد. مقادیر طبق روش قبلی با تغییر ذخیره می‌شوند. رفتن به بخش دیگر یا خروج از برنامه حالت ویرایش را می‌بندد.

## بکاپ خودکار شبانهٔ JSON

بکاپ دستی و نسخه‌های برگشت قبلی حفظ شده‌اند. برای فعال‌سازی: تنظیمات → ویرایش، توکن و Chat ID ربات را تنظیم کن، در بخش بکاپ شبانه مقصدهای تلگرام و درایو را به‌دلخواه فعال کن. زمان برنامه‌ریزی ساعت ۲۲ به وقت محلی گوشی است. بکاپ خودکار به‌صورت پیش‌فرض خاموش است و با فعال‌سازی، تمام JSON شامل حساب‌ها و تنظیمات حساس بدون رمزگذاری ارسال می‌شود؛ این همان انتخاب کاربر است.

با هر تغییر، آخرین نسخهٔ همان روز در حافظهٔ خصوصی آماده می‌شود. تغییرات متوالی در نسخهٔ همان روز ادغام می‌شوند. بکاپِ آمادهٔ ساعت ۲۲ با نامی مانند `nasie-1405-09-06.json` و تاریخ شمسی ارسال می‌شود. JSON دستی، نسخهٔ محلی و گزارش اکسل هم در نام فایل تاریخ شمسی دارند. اگر اینترنت یا سرویس در دسترس نباشد، نسخه در صف باقی می‌ماند؛ وضعیت ارسال هر مقصد جدا ذخیره می‌شود. موفقیت تلگرام، نسخهٔ ناموفق درایو را حذف نمی‌کند و بالعکس. فایل فقط بعد از تأیید موفق هر دو مقصد انتخاب‌شده از صف ارسال پاک می‌شود؛ حساب اصلی هرگز توسط Worker تغییر نمی‌کند. نتیجهٔ نامشخص HTTP ممکن است در تلگرام یک فایل تکراری ایجاد کند؛ نام و شناسهٔ محتوا یکسان است. درایو با شناسهٔ محتوا از تکرار جلوگیری می‌کند.

Android WorkManager در پس‌زمینه و پس از راه‌اندازی مجدد گوشی کار را پیگیری می‌کند؛ ساعت دقیق به Doze، محدودیت باتری و شبکه وابسته است. در پوکو، دسترسی اجرای پس‌زمینه/شروع خودکار برنامه را مجاز کن و محدودیت شدید باتری را بردار. Force stop و خاموش بودن گوشی اجرای کار را متوقف می‌کنند؛ با باز کردن دوباره، صف بررسی می‌شود. «آماده‌سازی و تلاش مجدد» به‌صورت دستی صف را بررسی می‌کند. وضعیت و تاریخ آخرین ارسال در همان بخش نمایش داده می‌شوند. فایل‌های در صف با حذف برنامه یا Clear storage از بین می‌روند، پس بکاپ دستی بیرونی را حفظ کن.

### اتصال یک‌بارهٔ گوگل‌درایو

۱. نسخهٔ release را با کلید امضای ثابت بساز.
۲. در Google Cloud یک پروژه ایجاد کن، Google Drive API را فعال و صفحهٔ OAuth Consent را تنظیم کن؛ برای حالت آزمایشی حساب گوگل خودت را در Test users قرار بده.
۳. OAuth Client از نوع Android بساز. Package و SHA-1 را از راهنمای گوگل‌درایو داخل تنظیمات برنامه کپی کن؛ این اطلاعات برای همان APK است. نسخهٔ test شناسه و امضای جدا دارد و امضای سرور debug ممکن است هر بار عوض شود.
۴. در برنامه «اتصال / مجوز گوگل‌درایو» را بزن و حساب خودت را انتخاب کن. دسترسی drive.file فقط برای فایل‌هایی است که خود برنامه می‌سازد/به آن داده می‌شوند.
۵. بکاپ خودکار و مقصد درایو را فعال کن، «آماده‌سازی و تلاش مجدد» را بزن و وجود فایل نام‌دار را در Drive بررسی کن. تا اتصال واقعی و مشاهدهٔ فایل، ارسال درایو تأییدشده نیست.

راهنمای رسمی: https://developer.android.com/identity/authorization
مدل آفلاین: https://alphacephei.com/vosk/models

## تقویم صفحهٔ تغییرات

در بالای صفحهٔ تغییرات، ماه و سال شمسی را انتخاب کن و روز موردنظر را بزن. «امروز» به تاریخ فعلی برمی‌گردد. مجموع‌های روز مربوط به تمام تغییرات همان روز هستند؛ روزهای شلوغ در صفحه‌های ۱۰۰تایی نمایش داده می‌شوند. در نسخهٔ ۲۲، انتخاب روز تقویم علاوه بر نمایش گزارش، تاریخ نسیه و پرداخت‌های بعدی را هم تعیین می‌کند؛ این تاریخ روی فرم ثبت دیده می‌شود. تا تغییر روز، همهٔ ثبت‌های دستی و صوتی در همان روز می‌مانند. سررسید از همان تاریخ محاسبه می‌شود، ولی زمان واقعی انجام عملیات جدا حفظ می‌شود. رفتن به داشبورد یا خروج از برنامه انتخاب را به امروز برمی‌گرداند. انتخاب روز به‌تنهایی دادهٔ قبلی حساب‌ها را تغییر نمی‌دهد. تغییر روز بر اساس نیمه‌شب محلی گوشی محاسبه می‌شود و روزهای تغییر ساعت نیز پوشش داده می‌شوند.

در نسخهٔ ۱۸ انیمیشن شمارنده‌ها تنها یک حلقهٔ فعال دارند؛ تغییر سریع روزها در یک فریم ادغام می‌شود و بخش تغییرات بدون انیمیشن ورود و فیلتر شیشه‌ای سنگین نمایش داده می‌شود. این اصلاح‌ها برای رفع پرش و خالی شدن صفحه انجام شده‌اند؛ علت قطعی رخداد قبلی بدون گزارش گوشی قابل اثبات نیست.

## اگر ساخت قرمز شد

اجرای قرمز را باز کن و اولین مرحلهٔ ناموفق و خطای آن را بررسی کن. نیاز به کلیدهای امضا در release با پیام مشخص متوقف می‌شود. اگر Check accounting، Build یا lint خطا داد، همان متن خطا را برای رفع مشکل بفرست؛ اطلاعات secret یا فایل بکاپ حساب‌ها را نفرست. گزارش lint، اگر ساخته شده باشد، در Artifacts با نام android-lint-report است.
