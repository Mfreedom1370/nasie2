# ساخت نسخهٔ نصبی دفتر نسیه از گیت‌هاب

این پروژه شامل نسخهٔ وب و پروژهٔ اندروید است. فایل APK هنوز روی این کامپیوتر ساخته نشده؛ ساخت و بررسی Android lint در GitHub Actions انجام می‌شود. تست‌های محلی، شبیه‌سازی هستند و جای تست روی گوشی را نمی‌گیرند.

## ۱. آپلود

ZIP آماده را استخراج کن و **محتویات آن** را به ریشهٔ مخزن قبلی ببر: index.html و پوشه‌های css، js، android، scripts، tests و **.github** باید کنار هم باشند. خود ZIP یا یک پوشهٔ اضافه دور پروژه را آپلود نکن. پوشهٔ .github ممکن است در انتخاب فایل پنهان باشد؛ حتماً وجود `.github/workflows/android-apk.yml` را در گیت‌هاب بررسی کن. اگر فایل در آپلود انتخاب نشد، Add file → Create new file را بزن، این مسیر را دقیق وارد کن و محتوای فایل محلی را کپی کن. فایل‌های قدیمیِ build workflow مربوط به پروژهٔ دیگری را همراه این پروژه اجرا نکن.

آپلود با Add file → Upload files → Commit changes انجام می‌شود. برای اجرای دستی، این فایل‌ها باید در شاخهٔ پیش‌فرض مخزن باشند. این مسیر با GitHub Pages جداست؛ Pages برای APK لازم نیست.

## ۲. ساخت آزمایشی

Actions → Build Android APK → Run workflow → build_type: **test** → Run workflow.
پس از سبز شدن اجرا، همان اجرا را باز کن؛ پایین صفحه در Artifacts، **nasie-test-apk** را دانلود کن. ZIP خروجی را باز کن و فایل app-debug.apk داخل آن را نصب کن. در صورت نیاز اجازهٔ نصب از مرورگر/مدیر فایل را در اندروید بده.

این نسخه فقط برای آزمایش با حساب نمونه است. شناسهٔ آن `ir.nasie.offline.test` است؛ امضای debug سرور ثابت تضمین‌شده نیست. برای نگهداری حساب واقعی و به‌روزرسانی‌های بعدی، نسخهٔ release را بساز. test و release دو برنامهٔ جدا هستند و اطلاعات خودکار بین آن‌ها منتقل نمی‌شود. اگر نصب debug جدید خطای امضا داد، ابتدا بکاپ بگیر؛ برای حذف نسخهٔ دارای حساب عجله نکن.

## ۳. ساخت نسخهٔ اصلی با امضای ثابت

اگر کلید امضای همین برنامه را از قبل داری، آن را نگه دار. این پروژه شناسهٔ `ir.nasie.offline` دارد؛ تا شناسه و کلید نسخهٔ قبلی مشخص نباشد، نمی‌توان آن را به‌روزرسانی مستقیم APK قدیمی دانست.

اگر کلید نداری، روی کامپیوتر Java JDK 17 نصب کن، PowerShell جدید را در پوشهٔ پروژه باز کن و اجرا کن:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\create-signing-key.ps1
```

این دستور فقط کلید می‌سازد؛ Android Studio لازم ندارد. کلید و چهار فایل TXT در پوشهٔ `Nasie-signing-private` داخل پوشهٔ کاربری ساخته می‌شوند؛ خارج از پروژه. از این پوشه یک نسخهٔ خصوصی و امن نگه دار. این فایل‌ها را به بخش Code مخزن، پیام یا Issue نفرست. برای آپدیت‌های بعدی کلید جدید نساز.

در مخزن: Settings → Secrets and variables → Actions → New repository secret. چهار secret زیر را با **محتوای** فایل TXT هم‌نام بساز:

- ANDROID_KEYSTORE_BASE64
- ANDROID_STORE_PASSWORD
- ANDROID_KEY_ALIAS
- ANDROID_KEY_PASSWORD

حالا Actions → Build Android APK → Run workflow → build_type: **release**.
خروجی **nasie-release-apk** شامل app-release.apk امضاشده است. شمارهٔ نسخه با هر اجرای همین workflow افزایش می‌یابد. برای نسخه‌های بعدی از همین مخزن، همین workflow، همین شناسه و همین کلید استفاده کن؛ جابه‌جایی مخزن/بازنشانی شمارنده ممکن است به تنظیم versionCode نیاز داشته باشد.

## ۴. انتقال حساب‌ها و بررسی گوشی

قبل از انتقال، در برنامهٔ قبلی خروجی JSON بگیر و وجود فایل را بررسی کن. نسخهٔ اصلی APK را نصب کن، بکاپ را از تنظیمات وارد کن و تعداد مشتری‌ها، تراکنش‌ها و چند مانده‌حساب را با نسخهٔ قبلی مقایسه کن. نسخهٔ قبلی را تا پایان بررسی حفظ کن. اطلاعات مرورگر یا APK دیگری خودکار به این برنامه منتقل نمی‌شود.

ابتدا با حساب نمونه این موارد را روی گوشی بررسی کن:

- در حالت پرواز برنامه را باز کن، مشتری و تراکنش بساز، برنامه را کامل ببند و دوباره باز کن؛ مانده باید حفظ شود.
- خروجی JSON بگیر، محل ذخیره را انتخاب کن و پیام «فایل بکاپ ذخیره شد» را ببین. لغو پنجره نباید پیام موفقیت بدهد. سپس فایل را در برنامه وارد کن و مانده را بررسی کن.
- میکروفون را امتحان کن؛ متن و برداشت‌های دیگر باید قبل از ثبت قابل بازبینی باشند. هیچ صدا یا متن موقتی خودکار تراکنش ثبت نمی‌کند.
- با همان کلید یک release جدید بساز و روی قبلی نصب کن؛ حساب نمونه باید باقی بماند.

## آفلاین و نگهداری اطلاعات

تمام HTML، جاوااسکریپت، فونت‌ها و کتابخانهٔ اکسل داخل APK قرار می‌گیرند. حساب‌ها در حافظهٔ خصوصی اندروید ذخیره می‌شوند؛ ثبت فقط بعد از نتیجهٔ موفق نوشتن حافظه معتبر است. نسخهٔ قبلی حساب، بکاپ پیش از بازیابی و سه بکاپ روزانهٔ محلی حفظ می‌شوند. نسخهٔ نصبی به Web Locks مرورگر وابسته نیست؛ Activity از نوع singleTask است. بکاپ خودکار سیستم‌عامل خاموش است؛ بکاپ بیرون از برنامه همچنان ضروری است. حذف برنامه یا Clear storage اطلاعات داخل آن را پاک می‌کند.

میکروفون با اینترنت از سرویس معمول گفتار گوشی با درخواست زبان فارسی استفاده می‌کند. بدون اینترنت، سرویس گفتار روی دستگاه فعال می‌شود؛ قطع ارتباط سرویس آنلاین نیز یک بار به حالت آفلاین برمی‌گردد. آماده بودن مدل فارسی ضروری است. متن موقت، مشتری‌های نزدیک را نشان می‌دهد؛ پس از پایان گفتار، ابتدا مشتری را انتخاب می‌کنی و سپس مبلغ و نوع ثبت را جداگانه تأیید می‌کنی. هیچ نتیجهٔ صوتی خودکار حساب را تغییر نمی‌دهد. ممکن است سرویس آنلاین صدا را برای پردازش ارسال کند؛ برنامه فهرست مشتری‌ها یا دفتر حساب‌ها را به سرویس گفتار ارسال نمی‌کند. تشخیص آفلاین به اندروید ۱۲ به بالا و پشتیبانی سرویس گوشی نیاز دارد.

تلگرام و دستیار API موجود، در صورت تنظیم و استفاده، اینترنت می‌خواهند؛ بسته‌بندی APK آن‌ها را آفلاین نمی‌کند. فقط گزارش اکسل در مسیر ارسال قبلی تلگرام حفظ شده؛ JSON از این نسخه فقط با انتخاب محل ذخیره صادر می‌شود.

## گفتار فارسی آفلاین روی پوکو F5، اندروید ۱۵

۱. با اینترنت، Google و Speech Recognition & Synthesis را در فروشگاه به‌روز کن.
۲. در تنظیمات همین برنامه «بررسی / دانلود مدل فارسی» را بزن. اگر مدل نصب باشد، پیام آماده بودن نمایش داده می‌شود؛ در غیر این صورت، اگر سرویس فارسی را ارائه کند، دانلود درخواست می‌شود.
۳. پیام «در صف» به معنی آماده بودن نیست؛ بعداً دوباره بررسی کن.
۴. بعد از پیام آماده بودن، حالت پرواز را روشن کن و میکروفون را با یک مشتری نمونه امتحان کن.
۵. اگر سرویس مدل فارسی ارائه نکند، از طریق آن سرویس قابل نصب نیست. در تنظیمات گوشی «تایپ صوتی Google» یا «تشخیص گفتار آفلاین» را جست‌وجو کن؛ فقط اگر فارسی در فهرست دانلود وجود دارد، دریافتش کن. نام و موجود بودن این بخش به نسخهٔ سرویس گوشی بستگی دارد. افزودن کیبورد فارسی به‌تنهایی مدل گفتار آفلاین نصب نمی‌کند. حتی بدون مدل صوتی، حسابداری و جست‌وجوی دستی آفلاین کار می‌کنند.

بررسی و درخواست دانلود داخل برنامه به اندروید ۱۳ به بالا نیاز دارد؛ گزارش پیشرفت و پایان دانلود به اندروید ۱۴ به بالا. برنامه مدل مستقل فارسی همراه ندارد و نصب مدلِ ارائه‌نشده را تضمین نمی‌کند.

## تقویم صفحهٔ تغییرات

در بالای صفحهٔ تغییرات، ماه و سال شمسی را انتخاب کن و روز موردنظر را بزن. «امروز» به تاریخ فعلی برمی‌گردد. مجموع‌های روز مربوط به تمام تغییرات همان روز هستند؛ روزهای شلوغ در صفحه‌های ۱۰۰تایی نمایش داده می‌شوند. جابه‌جایی تاریخ، دادهٔ حساب‌ها را تغییر نمی‌دهد. تغییر روز بر اساس نیمه‌شب محلی گوشی محاسبه می‌شود و روزهای تغییر ساعت نیز پوشش داده می‌شوند.

در نسخهٔ ۱۸ انیمیشن شمارنده‌ها تنها یک حلقهٔ فعال دارند؛ تغییر سریع روزها در یک فریم ادغام می‌شود و بخش تغییرات بدون انیمیشن ورود و فیلتر شیشه‌ای سنگین نمایش داده می‌شود. این اصلاح‌ها برای رفع پرش و خالی شدن صفحه انجام شده‌اند؛ علت قطعی رخداد قبلی بدون گزارش گوشی قابل اثبات نیست.

## اگر ساخت قرمز شد

اجرای قرمز را باز کن و اولین مرحلهٔ ناموفق و خطای آن را بررسی کن. نیاز به کلیدهای امضا در release با پیام مشخص متوقف می‌شود. اگر Check accounting، Build یا lint خطا داد، همان متن خطا را برای رفع مشکل بفرست؛ اطلاعات secret یا فایل بکاپ حساب‌ها را نفرست. گزارش lint، اگر ساخته شده باشد، در Artifacts با نام android-lint-report است.
